# Lab Review — корпоративный сайт маркетингового агентства

Портфолио-платформа и каталог услуг для агентства (SEO, Яндекс.Директ, реклама на Авито, веб-разработка). Сайт построен на Django как полностью управляемая из админки система: контент кейсов, состав команды и привязки сотрудников к услугам редактируются без участия разработчика, а кейсы дополнительно импортируются из Google Sheets одной кнопкой.

**Живой сайт:** https://lab-review.ru/

## Стек

- **Backend:** Python 3.14, Django 6.0.4
- **БД:** SQLite
- **Зависимости:** минимальные — `django-nested-admin` (вложенные инлайны в админке) и `Pillow` (обработка изображений).
- **Frontend:** без фреймворков — семантический HTML, CSS на кастомных свойствах (дизайн-токены), ванильный JavaScript, инлайн-SVG иконки, шрифт Manrope.
- **Интеграции:** Google Sheets API (импорт кейсов), Telegram Bot API (приём заявок), Яндекс.Метрика.
- **Деплой:** Beget, Passenger/WSGI, `git pull` + перезапуск, `collectstatic`. Секреты в `.env` через `python-dotenv`.

## Роль

Единственный разработчик, full-stack: контентная модель и архитектура, бэкенд и админка, ETL-импорт, интеграции, SEO, фронтенд и деплой.

## Архитектура

Проект разбит на два Django-приложения с чёткой зоной ответственности:

- **`cases`** — кейсы (портфолио): модели, гибкий конструктор контента, админка, импорт из таблиц, sitemap.
- **`services`** — 12 посадочных страниц услуг, единый базовый шаблон, приём заявок, главная страница.

Сотрудники вынесены в единую базу (`Employee`) и переиспользуются и в кейсах (блок «Команда»), и на страницах услуг — без дублирования данных.

## Ключевой функционал

### Конструктор страниц кейса

Страница кейса собирается из произвольной последовательности контентных блоков (модель `CaseBlock`), 7 типов на выбор: вводный текст, «задача + резюме проекта», сетка задач, двухколоночный контент-блок, блок результатов с цифрами, команда, CTA. Порядок и видимость каждого блока управляются отдельно. Под каждый тип блока — свои дочерние элементы через вложенные инлайны; лишние поля в админке прячутся динамически в зависимости от типа блока (кастомный JS).

### Двухрежимная админка на прокси-моделях

Кейсы физически хранятся в одной таблице, но в админке разнесены на два раздела через прокси-модели:

- **«Кейсы по веб-разработке»** — лента изображений, своя страница-шаблон, исключение из sitemap и `noindex`.
- **«Кейсы (Авито / SEO / Директ)»** — полный конструктор блоков и метрик.

Каждый раздел импортирует данные из своей таблицы Google Sheets, направление проставляется автоматически.

### Импорт кейсов из Google Sheets

Кастомная management-команда тянет данные через Google Sheets API и разворачивает строку таблицы в полноценный кейс со всеми блоками, метриками, тегами и командой.

- **Идемпотентность:** `update_or_create` по slug — повторный импорт обновляет, а не плодит дубли.
- **Локальное кэширование изображений:** картинки по URL скачиваются в media, имя файла — MD5 от URL, повторно уже скачанные файлы не качаются.
- **Устойчивость:** каждая строка импортируется в отдельной транзакции — сбой на одном кейсе не ломает остальные.
- **Изолированное логирование:** ход импорта и трейсбеки пишутся в отдельный файл-лог.
- Автосоздание тегов с уникальными слагами и автопривязка сотрудников к единой базе.

Запуск — кнопкой прямо из админки (через `call_command`) либо из консоли.

### Приём заявок в Telegram

Форма заявки (модальное окно + формы на страницах услуг и контактов) отправляет данные AJAX-запросом на серверный эндпоинт, который пересылает их в Telegram через Bot API. Реализовано на стандартной библиотеке (`urllib`), без сторонних HTTP-клиентов. На фронте — маска телефона, валидация полей, счётчик символов, автовысота текстового поля.

### Каталог услуг

12 посадочных страниц на едином базовом шаблоне с переопределяемыми блоками (герой, тарифы, «что входит», этапы работ, команда, FAQ, рекомендованные услуги, CTA). Состав команды на странице настраивается через промежуточную модель с сортировкой; если страница не настроена — показываются все сотрудники (graceful fallback).

### Фильтрация и поиск по кейсам

Фильтрация по направлению, отрасли и тегам; списки фильтров строятся динамически от выбранного направления. Реализован обход ограничения SQLite — регистронезависимый поиск по кириллице (`icontains` для кириллицы в SQLite регистрозависим) через перебор вариантов регистра.

### SEO-инфраструктура

- Автоматический `sitemap.xml` (опубликованные кейсы + статические страницы), с исключением dev-кейсов и Авито-услуг.
- Поля `meta_title` / `meta_description` на каждом кейсе с фолбэком на основной заголовок и описание.
- Человекочитаемые URL-слаги с поддержкой Unicode.
- Набор 301-редиректов со старых адресов на новые SEO-ориентированные URL.
- `noindex` для технических dev-кейсов.

### Прочее

- Кастомные страницы ошибок 404 / 403 / 500.
- Cookie-баннер с сохранением согласия в localStorage.
- Фиксированный хедер с мегаменю услуг, скрывающийся при скролле; адаптивное мобильное меню-аккордеон.
- Полная адаптивная вёрстка, лайтбокс для изображений в кейсах.

## Чем интересен проект

- Гибкая контентная модель (блочный конструктор страниц) вместо жёстко зашитой вёрстки.
- Глубокая кастомизация Django-админки: вложенные инлайны, прокси-модели, динамическое поведение формы, кастомные admin-actions.
- Надёжные ETL-команды с идемпотентностью, потранзакционной обработкой, кэшированием ресурсов и изолированным логированием.
- Интеграции со сторонними API (Google Sheets, Telegram) на чистой стандартной библиотеке.
- Самостоятельная фронтенд-разработка без фреймворков.
